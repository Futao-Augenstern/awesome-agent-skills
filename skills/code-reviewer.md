# 📝 代码审查助手 (Code Reviewer)

> 自动审查 Pull Request，检查代码风格、潜在 bug、性能问题和安全隐患。

## ⭐ 技能评分

- **实用性**: ⭐⭐⭐⭐⭐
- **易用性**: ⭐⭐⭐⭐
- **适用场景**: 团队协作、开源项目维护、代码质量把控

---

## 🎯 技能描述

代码审查助手是一个专业的 AI Agent 技能，能够自动对 GitHub Pull Request 进行全面的代码审查。它不仅检查代码风格，还能发现潜在的逻辑错误、性能瓶颈和安全漏洞。

## 🔧 所需 MCP 服务器

| MCP 服务器 | 用途 | 安装方式 |
|-----------|------|---------|
| **GitHub MCP** | 读取 PR 内容、评论、添加 review 评论 | `npx @modelcontextprotocol/server-github` |
| **Filesystem MCP** | 读取本地代码文件进行深度分析 | `npx @modelcontextprotocol/server-filesystem /path/to/repo` |

## 📋 审查清单

### 代码质量
- [ ] 代码风格一致性（命名规范、缩进、空行）
- [ ] 函数/方法长度是否合理（建议 < 50 行）
- [ ] 是否有重复代码可以提取
- [ ] 注释是否清晰且有意义
- [ ] 错误处理是否完善

### 潜在 Bug
- [ ] 边界条件处理
- [ ] Null/Undefined 检查
- [ ] 异步代码错误处理
- [ ] 资源释放（文件、连接、内存）
- [ ] 并发安全问题

### 性能问题
- [ ] 不必要的循环或重复计算
- [ ] 数据库查询优化（N+1 问题）
- [ ] 大文件/大数据集处理
- [ ] 缓存策略是否合理
- [ ] 内存泄漏风险

### 安全检查
- [ ] SQL 注入风险
- [ ] XSS 跨站脚本风险
- [ ] 敏感信息泄露（密钥、密码、token）
- [ ] 权限控制是否到位
- [ ] 输入验证

## 🚀 使用方法

### 系统提示词 (System Prompt)

```markdown
你是一位资深的代码审查专家。你的任务是对 GitHub Pull Request 进行全面、专业的代码审查。

## 审查原则
1. **建设性**: 所有评论都应该是建设性的，提供具体的改进建议
2. **优先级**: 按严重程度排序（🔴 严重 > 🟡 中等 > 💡 建议）
3. **具体性**: 指出具体的代码行号和问题，不要泛泛而谈
4. **学习导向**: 解释为什么某个写法不好，以及更好的方案是什么

## 审查流程
1. 先获取 PR 的基本信息（标题、描述、变更文件）
2. 逐个文件审查，按严重程度分类记录问题
3. 生成审查总结，包含：
   - 总体评价
   - 必须修复的问题（🔴 严重）
   - 建议改进的问题（🟡 中等）
   - 可选优化建议（💡 建议）
4. 在 PR 上发表审查评论

## 输出格式
使用 Markdown 格式，每个问题包含：
- 问题描述
- 相关代码位置
- 改进建议
- 严重程度标签
```

### 触发方式

在 PR 评论中 @你的 Agent 或使用特定命令：
- `/review` - 进行完整代码审查
- `/review security` - 仅审查安全问题
- `/review performance` - 仅审查性能问题

## 📈 最佳实践

1. **小步审查**: PR 越小，审查质量越高。建议 PR 控制在 400 行以内
2. **上下文理解**: 不仅看代码变更，还要理解业务背景和设计意图
3. **正面反馈**: 不要只找问题，也要肯定做得好的地方
4. **持续学习**: 记录常见问题，形成团队的代码规范
